# Forgebox — Architecture Contract (v1)

Forgebox is a **transactional try-then-commit execution backend** for Hermes Agent.
It lets an agent experiment inside a disposable snapshot of a Git repo (dirty tree
included) and then review, apply with rollback protection, or discard the result.

This file is the single source of truth for module layout and public interfaces.
Parallel build tasks each own a disjoint set of files and code against the
signatures below. Do not edit this file. Do not edit pyproject.toml, LICENSE,
.gitignore, or ARCH.md. Do not run `git commit`/`git push`/`git add` in the repo.

## Product behavior (the contract everything must serve)

1. `begin`: capture the repo's *dirty* state (staged + unstaged + untracked)
   into an ephemeral snapshot commit, and create a detached git worktree for it.
2. While active, the agent's tool calls run inside the worktree. File-path
   arguments are rewritten from the base repo to the worktree. Writes outside
   the base repo are blocked for known file-path arguments (advisory only).
3. Every tool call (command, exit code, changed files, tests run) is journaled.
4. `preflight`: compute the diff (snapshot → worktree) and check whether any
   file it touches has changed in the real repo since the snapshot. Conflicts
   are surfaced, never silently clobbered.
5. `apply`: stage and check the worktree diff, then install with original-file
   backups and rollback on ordinary I/O failures. This is not crash-atomic or
   isolated from external editors. Optional commit message.
6. `discard`: delete the worktree, prune git metadata, drop the snapshot ref.

### hooks.py (Hermes plugin entry points)
Hooks receive Hermes keyword arguments, including `tool_name`, `args`,
`session_id`, and `task_id`, plus forward-compatible `**kwargs`.
- `pre_tool_call` returns `{"action": "modify", "args": rewritten_args}`,
  `{"action": "block", "message": "Forgebox: path outside sandbox"}`, or `None`.
  Known file-path arguments and command working directories are redirected.
  Shell source is preserved verbatim, not parsed as paths or a security policy.
- `post_tool_call` records command, exit code, path hints, and timestamp.
- `post_approval_response` records `choice` and `decided_by` only. It never
  applies changes. Apply explicitly through the CLI or dashboard/Desktop.

## Constraints

- Python >= 3.10, **stdlib only** (subprocess/shutil/json/etc.) + the `git`
  CLI. No third-party runtime deps. No FUSE.
- Cross-platform intent: Linux/macOS (POSIX). Windows guards allowed but not required.
- Never modify the user's real git index or worktree except in `apply`.
- Hooks provide best-effort path/cwd redirection, not containment. Absolute shell paths, subprocesses, network calls, and dynamically generated writes can escape.
- Tests use pytest (dev-only): run `python -m pytest tests/ -q` from repo root.
- Each build task touches ONLY its own file set (listed above). A module you
  import but do not own may not exist yet — code defensively; integration is
  verified after fan-in.
- Report honestly in your summary: what you built, what you verified (files
  read back / tests run), and any known gaps.
